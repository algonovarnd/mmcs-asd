# Бинарный поиск

## Бинарный поиск в массиве

Представьте игру, где нужно угадать число от 1 до 100, задавая только вопросы, на которые можно отвечать «да» или «нет». Самый эффективный способ - каждый раз спрашивать, больше ли число середины диапазона. Например, начав с 50, вы уточняете: «Число больше 50?». Если да, сужаете поиск до диапазона от 51 до 100, если нет - до 1-50. Этот подход эффективен, потому что на каждом шаге количество возможных чисел уменьшается вдвое. В отличие от последовательного перебора каждого числа, где проверка идет по одному варианту за раз, здесь поиск сводится к минимальному количеству шагов, быстро приводя к нужному числу. Такой метод деления пополам и сокращения области поиска лежит в основе бинарного поиска, который используется для быстрого нахождения элемента в отсортированных данных.

Теперь давайте рассмотрим другой пример: поиск страницы в книге. Представьте, что вам нужно найти страницу 567 в книге, которая насчитывает 1000 страниц. Самый быстрый способ - открыть ее посередине, на странице 500, и проверить номер. Если 567 больше, вы понимаете, что нужная страница находится в правой половине, и продолжаете поиск там. Если меньше, то переключаетесь на левую половину. Повторяя этот процесс, вы каждый раз сокращаете количество страниц для поиска вдвое, пока не дойдете до нужной. Этот метод, как и в игре с угадыванием чисел, использует принцип деления пополам и минимизирует количество шагов.

Рассмотрим задачу поиска элемента в массиве. Представьте, что у вас есть массив чисел, например, `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`, и нужно быстро найти, содержится ли в нем число 23. Вместо того чтобы проверять каждый элемент по порядку, как при последовательном поиске, мы можем использовать бинарный поиск. Для этого массив должен быть отсортирован, потому что идея алгоритма основывается на сравнении искомого элемента со средним элементом текущего диапазона. Например, начав с середины массива, вы можете сразу исключить половину элементов: если 23 меньше среднего значения, все элементы справа можно отбросить, потому что в отсортированном массиве они гарантированно больше. Без сортировки такой логики не получится, и метод не сможет работать, поскольку вы не будете уверены, где находится искомый элемент относительно текущего среднего значения.

Посмотрим на бинарный поиск с другой стороны. Представим, что все элементы массива можно разделить на две группы: те, которые меньше искомого числа $x$, и те, которые больше или равны $x$. Вместо того чтобы искать сам элемент $x$, мы будем искать границу между этими двумя группами. Так как изначально массив отсортирован, то все элементы, которые меньше $x$, окажутся слева от границы, а все, которые больше или равны $x$, - справа. Таким образом, задача сводится к нахождению этой границы.

Назовем элементы массива, которые меньше искомого числа $x$, **плохими**, а те, которые больше или равны $x$, - **хорошими**. Теперь, если мы ищем число $x$ в массиве, наша задача сводится к поиску **первого хорошего элемента**, то есть того элемента, который лежит сразу справа от границы между плохими и хорошими. Такой подход помогает упростить процесс, поскольку вместо поиска конкретного числа мы сосредотачиваемся на нахождении точки, с которой начинаются хорошие элементы.

Договоримся о терминах:

- **левый бинарный поиск** - хорошие ответы лежат слева;
- **правый бинарный поиск** - хорошие ответы лежат справа.

Теперь представим, что у нас есть отрезок массива $[l, r]$, где присутствуют как плохие, так и хорошие элементы. Это значит, что элемент с индексом $l$ - плохой, а с индексом $r$ - хороший. Для сокращения этого отрезка мы найдем середину, вычислив
```math
m = \left\lfloor \frac{l + r}{2} \right\rfloor,
```
и посмотрим на элемент с индексом $m$.

- Если элемент в середине **плохой**, это означает, что все элементы от $l$ до $m$ тоже плохие. Поэтому мы можем сдвинуть $l$ вправо, к значению $m$.
- Если элемент в середине **хороший**, это означает, что все элементы от $m$ до $r$ хорошие. В этом случае мы сдвигаем $r$ влево, к значению $m$.

Мы продолжаем этот процесс, попеременно сокращая отрезок, сдвигая $l$ и $r$ все ближе друг к другу. Процесс завершается, когда расстояние между $l$ и $r$ становится равным 1 (то есть $r - l = 1$). В этот момент граница между плохими и хорошими элементами найдена, а $r$ указывает на первый хороший элемент массива.

```cpp
while (r - l > 1) {
    int m = l + (r - l) / 2;
    if (a[m] >= x) {
        r = m;
    } else {
        l = m;
    }
}
// r указывает на первый "хороший" элемент
```

Теперь давайте подумаем, какие начальные значения нам стоит положить в переменные $l$ и $r$. Проблема тут в том, что $l$ должна всегда указывать на плохой элемент, а $r$ - на хороший. Однако не всегда очевидно, как это сделать в данной конкретной ситуации. Например, когда все элементы массива хорошие. В этом случае первый хороший элемент находится в самом начале массива, и значение $r$ должно быть равно 0. Другой случай - все элементы плохие. Здесь проблема в том, что первый хороший элемент отсутствует, и значение $r$ становится неопределенным, поскольку в массиве нет естественной границы между плохими и хорошими элементами.

Чтобы избежать этой неопределенности, мы добавляем виртуальные элементы: $-\infty$ с индексом $-1$, который всегда считается плохим, и $+\infty$ с индексом $n$, который всегда считается хорошим. Это гарантирует, что граница между плохими и хорошими элементами всегда существует, даже если все элементы массива принадлежат одной группе. Таким образом, начальные значения устанавливаются как $l = -1$ и $r = n$.

Обратим внимание, что значение $n$ никогда не получится для середины $m$, потому что по формуле $\left\lfloor \frac{l + r}{2}\right\rfloor$ середина всегда будет строго меньше $r$. Значение $-1$ теоретически могло бы получиться, если бы $l$ и $r$ стали соседними, но это невозможно, так как середина вычисляется только тогда, когда $r - l > 1$. Таким образом, $m$ всегда остается внутри допустимого диапазона индексов массива, что исключает обращение к несуществующим элементам.

Этот алгоритм всегда находит первый элемент, который удовлетворяет условию $a[i] \ge x$. Если значение $x$ присутствует в массиве, то это будет индекс самого левого вхождения $x$. Поиск заканчивается, когда $l$ и $r$ стали соседними, и $r$ указывает на первый "хороший" элемент.

Эта реализация бинарного поиска называется **правым бинарным поиском**, потому что в этой постановке хорошие ответы лежат справа.

Для того чтобы ответить на вопрос, был ли найден элемент $x$ в массиве, достаточно посмотреть на индекс, который вернет правый бинарный поиск. Если этот индекс равен $n$, это означает, что все элементы массива плохие относительно условия $a[i] \ge x$ (то есть меньше $x$), поэтому элемент $x$ не найден. Также элемент не будет найден, если под найденным индексом стоит число, не равное $x$.

```cpp
if (r == n || a[r] != x) {
    std::cout << "Элемент не найден\n";
} else {
    std::cout << "Элемент найден на позиции " << r << '\n';
}
```

Теперь мы поделим массив по-другому на две группы: хорошие элементы - это те, которые меньше или равны $x$, а плохие - те, которые больше $x$. Наша задача - найти последний хороший элемент, то есть самый правый элемент, который $\le x$. Для этого аналогично начинаем с границ: слева расположим виртуальный элемент $-\infty$ (всегда хороший), а справа - $+\infty$ (всегда плохой). Каждый раз находим середину массива и проверяем: если элемент хороший ($\le x$), сдвигаем левую границу вправо; если плохой ($> x$), сдвигаем правую границу влево. Когда границы почти сходятся, левая будет указывать на последний хороший элемент.

```cpp
while (r - l > 1) {
    int m = l + (r - l) / 2;
    if (a[m] <= x) {
        l = m;
    } else {
        r = m;
    }
}
// l указывает на последний "хороший" элемент
```

Этот алгоритм гарантированно находит последний хороший элемент, потому что он специально настроен на поиск самой правой границы группы элементов, удовлетворяющих заданному условию ($\le x$). Его называют **левым бинарным поиском**, потому что в этой постановке хорошие ответы лежат слева.

Для ответа на вопрос, был ли найден элемент $x$, необходимо проверить, что $l \neq -1$ и $a[l] = x$.

```cpp
if (l == -1 || a[l] != x) {
    std::cout << "Элемент не найден\n";
} else {
    std::cout << "Элемент найден на позиции " << l << '\n';
}
```

Обратите внимание, что если в отсортированном массиве присутствует несколько элементов, равных $x$, все они образуют некоторый непрерывный отрезок исходного массива. В таком случае правый бинарный поиск вернет индекс первого вхождения $x$, а левый бинарный поиск - индекс последнего. Таким образом, можно однозначно определить границы отрезка, содержащего все элементы, равные $x$.

## 2.2. Бинарный поиск по ответу

Рассмотрим следующую задачу.

#### Задача. Дипломы
Когда Петя учился в школе, он часто участвовал в олимпиадах по информатике, математике и физике. Так как он был достаточно способным мальчиком и усердно учился, то на многих из этих олимпиад он получал дипломы. К окончанию школы у него накопилось $n$ дипломов, причем, как оказалось, все они имели одинаковые размеры: $w$ в ширину и $h$ в высоту.

Сейчас Петя учится в одном из лучших университетов и живет в общежитии со своими одногруппниками. Он решил украсить свою комнату, повесив на одну из стен свои дипломы за школьные олимпиады. Так как к бетонной стене прикрепить дипломы достаточно трудно, он решил купить специальную доску из пробкового дерева, чтобы прикрепить ее к стене, а к ней - дипломы. Для того чтобы эта конструкция выглядела более красиво, Петя хочет, чтобы она была квадратной и занимала как можно меньше места на стене. Каждый диплом должен быть размещен строго в прямоугольнике $w \times h$. Дипломы запрещается поворачивать на 90 градусов. Прямоугольники, соответствующие различным дипломам, не должны иметь общих внутренних точек.

Напишите программу, которая вычислит минимальный размер стороны квадратной доски, которая потребуется Пете для размещения всех своих дипломов.

**Входные данные.** В единственной строке входных данных содержатся три числа: $w$, $h$, $n$ ($1 \le w, h, n \le 10^9$).

**Выходные данные.** Выведите единственное число - минимальный размер стороны квадратной доски.

**Пример**

| # | Входные данные | Выходные данные |
|:-:|:---------------|:----------------|
| 1 | `2 3 10`       | `9`             |
| 2 | `1 1 1`        | `1`             |

Формализуем задачу. Нужно найти минимальную сторону квадрата $s$, в котором можно разместить $n$ прямоугольников размера $w \times h$, не поворачивая их.

Если сторона квадрата равна $s$, то:

- по горизонтали в него помещается $\left\lfloor \frac{s}{w} \right\rfloor$ дипломов;
- по вертикали - $\left\lfloor \frac{s}{h} \right\rfloor$ дипломов.

Следовательно, всего в квадрат со стороной $s$ можно разместить
```math
\left\lfloor \frac{s}{w} \right\rfloor \cdot \left\lfloor \frac{s}{h} \right\rfloor
```
дипломов.

Наша задача - найти минимальное значение $s$, для которого выполняется
```math
\left\lfloor \frac{s}{w} \right\rfloor \cdot \left\lfloor \frac{s}{h} \right\rfloor \ge n.
```

Если при некотором значении $s$ все дипломы уже помещаются, то при любом большем значении стороны квадрата они тоже поместятся. Действительно, при увеличении $s$ величины $\left\lfloor \frac{s}{w} \right\rfloor$ и $\left\lfloor \frac{s}{h} \right\rfloor$ не уменьшаются, а значит, не уменьшается и их произведение.

Это означает, что ответ обладает свойством монотонности:

- маленькие значения $s$ - **плохие**, если дипломы не помещаются;
- достаточно большие значения $s$ - **хорошие**, если дипломы помещаются.

Тогда задача сводится к классическому бинарному поиску по ответу: нужно найти **минимальное хорошее** значение $s$.
Это в точности соответствует **правому бинарному поиску** из предыдущего раздела (ищем первый хороший элемент, хорошие ответы справа).

Для заданного $s$ проверка очень проста:

```cpp
bool check(long long s) {
    return (s / w) * (s / h) >= n;
}
```

Если функция `check(s)` возвращает `true`, значит квадрат со стороной $s$ подходит. Иначе - не подходит.

Левая граница должна быть плохой, правая - хорошей.

В качестве левой границы удобно взять
```math
l = 0.
```

Если $n \ge 1$, то в квадрат со стороной 0 ни один диплом не поместится, значит это точно плохое значение.

С правой границей чуть сложнее: заранее не всегда ясно, какое число точно окажется хорошим. Поэтому часто применяют такой прием: начинают с $r = 1$ и удваивают его, пока он не станет хорошим.

```cpp
long long r = 1;
while (!check(r)) {
    r *= 2;
}
```

Почему это обязательно сработает? Потому что рано или поздно сторона квадрата станет достаточно большой, чтобы вместить все дипломы. Например, при очень большом $r$ в квадрат точно поместится нужное количество прямоугольников.

После этого у нас будет:

- $l = 0$ - плохое значение;
- $r$ - хорошее значение.

В нашей задаче подобрать правую и левую границы можно более детально.

Заметим, что если сторона квадрата меньше $\max(w, h)$, то ни один диплом в такой квадрат поместить нельзя. Действительно, чтобы разместить диплом размером $w \times h$, сторона квадрата должна быть не меньше **обеих** сторон диплома. Если квадрат меньше хотя бы одной из них, диплом туда просто не войдет.

Действительно, при $s < \max(w, h)$ получаем
```math
\left\lfloor \frac{s}{w} \right\rfloor \cdot \left\lfloor \frac{s}{h} \right\rfloor = 0.
```

Следовательно, значение $l = \max(w, h) - 1$ точно является **плохим**.

Аналогично можно выбрать значение, которое гарантированно является **хорошим**, то есть позволяет разместить все дипломы.

Рассмотрим квадрат со стороной $s = n \cdot \max(w, h)$.

Пусть для определенности $\max(w, h) = h$. Тогда $s = n h$.

Посчитаем, сколько дипломов можно разместить:

- по вертикали: $\left\lfloor \frac{s}{h} \right\rfloor = n$;
- по горизонтали: $\left\lfloor \frac{s}{w} \right\rfloor \ge 1$, потому что $h \ge w$.

Следовательно,
```math
\left\lfloor \frac{s}{w} \right\rfloor \cdot \left\lfloor \frac{s}{h} \right\rfloor \ge 1 \cdot n = n.
```

То есть все дипломы гарантированно помещаются.

Таким образом, значение $r = n \cdot \max(w, h)$ точно является **хорошим**.

Также стоит обратить внимание, что при текущих ограничениях достаточно 64-битного целого типа данных (`long long` в C++, `int64` и т.д.).

#### Задача. Веревочки

С утра шел дождь, и ничего не предвещало беды. Но к обеду выглянуло солнце, и в лагерь заглянула СЭС. После проверки выяснилось, что бельевые веревки в жилых домиках не соответствуют нормам: в каждом домике должна быть ровно одна веревка, и все веревки должны иметь одинаковую длину.

В лагере есть $n$ исходных веревок, а домиков - $k$. Разрешается разрезать имеющиеся веревки на части. Требуется получить не менее $k$ веревочек одинаковой длины. При этом начальство хочет, чтобы длина этих веревочек была как можно больше.

Нужно найти **максимальную целую длину** веревочек, которую можно получить.

**Входные данные.**  
В первой строке заданы два числа - $n$ и $k$ ($1 \le n, k \le 10001$).
Далее в каждой из последующих $n$ строк записано по одному числу $a_i$ ($1 \le a_i \le 10^8$) - длина $i$-й бельевой веревки.

Длина веревки задана в сантиметрах. Все длины лежат в интервале от 1 сантиметра до 100 километров включительно.

**Выходные данные.**  
Выведите одно целое число - максимальную длину веревочки. Если получить хотя бы $k$ веревочек положительной длины невозможно, выведите `0`.

**Пример**

| # | Входные данные | Выходные данные |
|:-:|:---------------|:----------------|
| 1 | `4 11`<br>`802`<br> `743`<br> `457`<br> `539` | `200` |

Пусть мы хотим проверить, можно ли сделать $k$ кусков длины $x$.

Если длина очередной веревки равна $a_i$, то из нее можно нарезать
```math
\left\lfloor \frac{a_i}{x} \right\rfloor
```
кусков длины $x$.

Тогда всего из всех веревок получится
```math
\left\lfloor \frac{a_1}{x} \right\rfloor +
\left\lfloor \frac{a_2}{x} \right\rfloor + \dots +
\left\lfloor \frac{a_n}{x} \right\rfloor.
```

Если эта сумма не меньше $k$, значит длина $x$ нам подходит. Если меньше $k$, то такой длины добиться нельзя.

Таким образом, задача сводится к поиску максимального значения $x$, для которого выполняется неравенство
```math
\sum_{i=1}^{n} \left\lfloor \frac{a_i}{x} \right\rfloor \ge k.
```

Заметим, что если мы умеем нарезать $k$ кусков длины $x$, то и для любой меньшей длины это тоже будет возможно.

Действительно, если уменьшить длину куска, то из каждой веревки можно будет получить не меньше частей, чем раньше. А значит, суммарное количество кусков тоже не уменьшится.

Следовательно:

- маленькие значения $x$ - **хорошие**, если из них можно получить хотя бы $k$ кусков;
- слишком большие значения $x$ - **плохие**, если получить $k$ кусков уже нельзя.

Причем сначала идут хорошие значения, а потом плохие. Значит, здесь снова можно применить **бинарный поиск по ответу**.

Но теперь мы ищем не первый хороший элемент, а **последний хороший**, то есть максимальную длину, которая еще подходит.

Для фиксированной длины $x$ нужно посчитать, сколько всего кусков такой длины можно нарезать.

```cpp
bool check(long long x, const std::vector<long long>& ropes, long long k) {
    long long cnt = 0;
    for (long long a : ropes) {
        cnt += a / x;
        if (cnt >= k) {
            return true;
        }
    }
    return false;
}
```

Если `check(x)` возвращает `true`, то длина $x$ подходит.

**Левая граница.** В качестве левой границы удобно взять $l = 0$. Сама длина 0 не имеет практического смысла, но как фиктивная граница она очень удобна.

**Правая граница.** Длина искомого куска не может быть больше самой длинной исходной веревки. Поэтому можно взять
```math
r = \max(a_1, a_2, \dots, a_n) + 1.
```
Это значение точно плохое: ни из одной веревки нельзя получить даже одного куска такой длины.

Таким образом, стартуем с границ:
```math
l = 0, \qquad r = \max(a_i) + 1,
```
где $l$ - хорошее значение, а $r$ - плохое.

Важно: значение $x = 0$ в `check(x)` не проверяется. В бинарном поиске вычисляется середина
```math
m = l + \frac{r - l}{2},
```
и при условии цикла $r - l > 1$ и начальном $l = 0$ всегда выполняется $m \ge 1$.

Поскольку сначала идут хорошие ответы, а потом плохие, будем использовать **левый бинарный поиск** из предыдущего раздела (ищем последний хороший элемент, хорошие ответы слева). Если подходящей положительной длины нет, ответом останется `l = 0`.

Сложность алгоритма:

- одна проверка `check(x)` работает за $O(n)$;
- бинарный поиск делает $O(\log \max(a_i))$ итераций;
- итоговая сложность: $O(n \log \max(a_i))$.
